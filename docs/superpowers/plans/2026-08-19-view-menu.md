# View Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Marginal a View menu that exposes zoom, Show Source, and the status-bar readout — commands that today are reachable only by undocumented keystrokes or by clicking an unlabelled strip.

**Architecture:** Menu items carry an `action:` and no target, so AppKit routes them through the responder chain to `DocumentViewController` — the pattern `Export as PDF…` already uses. Checkmarks are derived in `validateMenuItem` when the menu opens, which keeps the status-bar readout per-window and unpersisted. `MarkdownTextView.keyDown` is left exactly as it is, as the fallback that catches the gestures a menu item cannot match.

**Tech Stack:** Swift 6, AppKit, XCTest, XcodeGen. macOS 14 deployment target.

## Global Constraints

- Ships in **0.11.0** on the existing `tables-0.11.0` branch and PR. Do **not** bump the version; append to the existing `## [0.11.0] — Unreleased` changelog section.
- **Every key equivalent is ASCII.** Zoom Out is hyphen-minus `-` (U+002D), never `−` (U+2212).
- **Success criterion:** all four gestures below still zoom afterwards, and none zooms by two steps.

| Gesture | Character seen | Extra modifier flags |
|---|---|---|
| ⌘= | `=` | — |
| ⌘⇧= (displayed ⌘+) | `+` | `.shift` |
| ⌘ + numpad `+` | `+` | `.numericPad` |
| ⌘- | `-` | — |

- `MarkdownTextView.keyDown` and `MarkdownTextViewShortcutDelegate` **survive unchanged**. Deleting them is out of scope and was explicitly reversed in the spec.
- The status-bar readout stays **per-window and in-memory**. Nothing new goes into `UserDefaults`.
- Run `xcodegen generate` after adding any new file. Never run two `xcodebuild` processes at once.
- Scope test runs with `-only-testing:MarginalTests/<ClassName>` — a full run is 7–10 minutes.

**Spec:** `docs/superpowers/specs/2026-08-19-view-menu-design.md`

```swift
// /tmp/spike-menu/main.swift
import AppKit

final class ProbeView: NSView {
    override var acceptsFirstResponder: Bool { true }
    override func keyDown(with event: NSEvent) {
        let chars = event.charactersIgnoringModifiers ?? "?"
        print("keyDown        chars=\(chars.debugDescription) flags=\(event.modifierFlags.rawValue) numpad=\(event.modifierFlags.contains(.numericPad))")
    }
}

final class Delegate: NSObject, NSApplicationDelegate {
    let probe = ProbeView()

    @objc func zoomIn(_ sender: NSMenuItem) { print("MENU ACTION    zoomIn via '\(sender.keyEquivalent)'") }
    @objc func zoomOut(_ sender: NSMenuItem) { print("MENU ACTION    zoomOut") }

    func applicationDidFinishLaunching(_ note: Notification) {
        let main = NSMenu()
        let viewItem = NSMenuItem()
        let view = NSMenu(title: "View")

        let zoomIn = NSMenuItem(title: "Zoom In", action: #selector(zoomIn(_:)), keyEquivalent: "+")
        zoomIn.keyEquivalentModifierMask = [.command]
        zoomIn.target = self
        view.addItem(zoomIn)

        // (c): can a hidden duplicate hold the cmd-= alternate?
        let alias = NSMenuItem(title: "Zoom In (alias)", action: #selector(zoomIn(_:)), keyEquivalent: "=")
        alias.keyEquivalentModifierMask = [.command]
        alias.target = self
        alias.isHidden = true
        view.addItem(alias)

        let zoomOut = NSMenuItem(title: "Zoom Out", action: #selector(zoomOut(_:)), keyEquivalent: "-")
        zoomOut.keyEquivalentModifierMask = [.command]
        zoomOut.target = self
        view.addItem(zoomOut)

        viewItem.submenu = view
        main.addItem(viewItem)
        NSApp.mainMenu = main

        let w = NSWindow(contentRect: NSRect(x: 0, y: 0, width: 460, height: 160),
                         styleMask: [.titled, .closable], backing: .buffered, defer: false)
        w.title = "Press: cmd-=, cmd-shift-=, cmd-numpad+, cmd--"
        w.contentView = probe
        w.center()
        w.makeKeyAndOrderFront(nil)
        w.makeFirstResponder(probe)
        NSApp.activate(ignoringOtherApps: true)
    }
}

let app = NSApplication.shared
let d = Delegate()
app.setActivationPolicy(.regular)
app.delegate = d
app.run()
```

## Self-review

**Spec coverage.** View menu between Edit and Window (Task 2); Zoom In/Out (2); Actual Size (2); Show Source with checkmark (3); single checkable Show Character & Word Count (4); responder-chain wiring with no target (2–4); checkmarks derived in `validateMenuItem` (3–4); readout stays per-window and unpersisted (4); `keyDown` retained (Task 5 pins it); `buildMainMenu` made internal for tests (2); spike (1); all four gestures tested (5); ASCII hyphen (2, 5); changelog under 0.11.0 (6).

**Not carried over from the spec deliberately:** the automated no-double-fire test. Asserting it requires `NSMenu.performKeyEquivalent(with:)` to dispatch through a real key window and responder chain, which an XCTest host does not reliably provide — a false negative there would be worse than no test. Task 1 answers it empirically and Task 6 step 5 item 2 checks it by hand.

**Type consistency.** `showsCounts` is the property name in Tasks 4's implementation, tests and validation branch. `toggleCharacterAndWordCount(_:)`, `toggleShowSource(_:)`, `zoomIn(_:)`, `zoomOut(_:)`, `actualSize(_:)` are spelled identically everywhere they appear. `FontSizing.defaultPointSize` is used in Tasks 2 and referenced in 2's test.
